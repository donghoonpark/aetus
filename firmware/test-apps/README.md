# AETUS Firmware Test Apps

This directory contains validation firmware, not reusable package source and not user-facing examples.

## Apps

| App | Purpose | Automation |
| --- | --- | --- |
| `qemu-telemetry` | SIL/QEMU fixture that emits a nanopb protobuf stream over UART so the ingest E2E test can POST the exact firmware-generated bytes into the backend stack. | Compile-checked by `Firmware Test Apps Build`; full QEMU-to-PostgreSQL flow is run by the manual `ESP32 QEMU E2E` workflow. |
| `qemu-signal-pool` | SIL/QEMU fixture that boots the signal sample pool module on a RISC-V ESP32 target and verifies pool allocation, queue-full overflow logging, and release counters without Wi-Fi or HTTP. | Compile-checked by `Firmware Test Apps Build`; runtime-checked by the manual `ESP32 QEMU E2E` workflow without requiring Wi-Fi or PostgreSQL. |
| `qemu-telemetry-heap` | SIL/QEMU fixture that verifies dynamic telemetry metrics: heap-backed metrics after the first four inline metrics, string/bytes deep-copy, producer deinit safety, queue item release counters, and heap recovery. | Compile-checked by `Firmware Test Apps Build`; runtime-checked by the manual `ESP32 QEMU E2E` workflow without requiring Wi-Fi or PostgreSQL. |
| `esp32c5-upload-smoke` | HIL firmware for a physical ESP32-C5 board. It consumes `firmware/esp32-aetus`, connects to Wi-Fi, syncs RTC, uploads telemetry, and can run randomized continuous upload mode. | Compile-checked by `Firmware Test Apps Build`; flash/monitor/runtime checks stay local because they require a board, Wi-Fi, and lab credentials. |
| `signal-frame-contract` | Compile-time contract app for dense signal frame memory limits. It fixes the 200Hz, 3s, 2-channel, int16 case at 2400 sample bytes and exercises the C signal frame setters. | Compile-checked by `Firmware Test Apps Build`; intended to catch regressions before a future PSRAM-backed signal sample memory pool changes ownership semantics. |

Keep new validation-only firmware here so `firmware/esp32-aetus` remains the portable embedded stack and `firmware/examples` remains focused on copyable user examples.
